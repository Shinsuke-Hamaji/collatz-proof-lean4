# Requirements Specification: Lean 4 Proof Module for JSP Submission (ID: JSP-000941)

## 1. Purpose and Scope

This document defines the requirements for the Lean 4 formal proof module and related submission artifacts for a pull request (PR) to `TheJustinSunPrize/awards` (hereafter, JSP).

* **Primary Objective**: To pass the PR cleanly by conforming to JSP submission rules and eliminating potential misunderstandings regarding formal verification.
* **Out of Scope**:
  * Introducing or claiming a custom framework, custom "Synchronized Infinity" concepts, or custom axioms.
  * Academic manuscript writing or peer-review correspondence for journals (such as *Theoretical Computer Science*), which is managed separately.

## 2. Submission Rules and Repository Compliance Requirements (Format)

1. **Modify Existing Catalog Entries Only**
   * External PRs must not directly add new files (such as under `problems/` or `candidates/`) and must update only the existing catalog entries specified by the repository rules.
2. **Self-Containment at PR Creation**
   * The diff, PR description, and code at the time of PR creation must make compliance with submission rules and verification conditions immediately clear.
3. **Minimal Diff Scope**
   * Avoid adding unnecessary files or making unrelated edits outside the target catalog entry.

## 3. Dependencies (Internal Dependencies, External Axioms, and Theorems)

### 3.1 Internal Dependencies

Within the module, dependencies flow strictly downward/forward from lower inductive types, depth functions, and bound theorems to the main theorem (no circular dependencies).

* **Step 1 (1D Structure)**
  * Define `Tree1D` (`root`, `step`), `depth1D`, and the bound theorem `depth1D_lt_value` (`depth1D t < n`).
  * Establish `exists_tree1D_with_bound` showing the existence of `Tree1D n` and its depth bound for `n ≥ 1`.
* **Step 2 (2D Structure)**
  * Using `Tree1D` and `depth1D_lt_value`, define `Tree2D` (`odd_root`, `double`) and `depth2D`.
  * Derive `depth2D_lt_value` (`depth2D t < n`) and `exists_tree2D_with_bound` using strong induction.
* **Step 3 (3D Structure and Hamaji Conjecture Correspondence)**
  * Using `Tree2D` and `depth2D_lt_value`, define `Tree3D` (`mod4_1_root`, `double`, `lift_from_2d`) and `depth3D`.
  * Derive `depth3D_lt_value` (`depth3D t < n`) and `exists_tree3D_with_bound`.
  * Frame the depth upper bound property on 3D trees (`depth3D t < n`) as the Hamaji Conjecture (Ceiling Bound).
* **Step 4 (Collatz Definition and Public Theorem)**
  * Define the standard `collatz` step function and the reachability proposition `CollatzConjecture` (`∀ n : ℕ, n > 0 → ∃ s : ℕ, (collatz^[s]) n = 1`).
  * Derive the public theorem `collatz_tree3D_depth_bound` (`∀ n > 0, ∃ t : Tree3D n, depth3D t < n`) from `exists_tree3D_with_bound`.

### 3.2 External Axioms and External Theorems

* **External Axioms**
  * Do not declare custom axioms (`axiom`).
  * Ensure axioms reported by `#print axioms collatz_tree3D_depth_bound` remain strictly within Lean's standard axioms (such as `propext` and `Quot.sound`).
* **External Theorems and Standard Library Elements**
  * Rely only on `Mathlib` and Lean 4 standard library types, arithmetic, and induction principles (such as natural numbers `ℕ`, function iteration, `omega`, `Nat.strong_induction_on`, and `Nat.le_induction`).
  * Treat `CollatzConjecture` strictly as a statement definition for reference, not as an imported external theorem or an asserted proof of reachability itself.

## 4. Technical Requirements for the Lean 4 Proof Module

1. **Clean Build in Standard Environment**
   * Build without errors under the repository's specified Lean 4 and Mathlib environment.
   * Contain zero uses of `sorry`.
2. **Axiom and Assumption Transparency**
   * Add no custom axioms (`axiom`).
   * Allow verification via `#print axioms` that dependencies are restricted to standard axioms.
3. **Removal of Custom Framework Terminology and Naming Cleanup**
   * Remove custom framework labels such as "Synchronized Infinity" or separate-framework assumptions from code, comments, and descriptions, relying instead on standard types and the standard `collatz` definition.
   * Consistently describe the Hamaji Conjecture (the 3D tree depth bound `depth3D t < n`) as a bound theorem proved using standard types and standard axioms.
4. **Accurate Scope Description**
   * Accurately state that the proof establishes upper bounds on depth (`depth1D` / `depth2D` / `depth3D`) for 1D, 2D, and 3D inductive tree structures (`∀ n > 0, ∃ t, depth3D t < n`), without conflating it with or overclaiming a proof of the Collatz reachability conjecture (`∀ n > 0, ∃ s, (collatz^[s]) n = 1`) itself.

## 5. Handling of Auxiliary Viewer (`JSP-000941.html`)

* Treat the HTML viewer for inspecting 1D, 2D, and 3D trajectories and depth metrics strictly as a local visualization and verification aid.
* Either keep it locally outside the PR or ensure its placement follows repository rules (such as avoiding unauthorized new file additions in PRs).
